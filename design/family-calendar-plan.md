# 가족 캘린더와 예정 지출 기획안

작성일: 2026-10-02 · 상태: 제안 · 앱 구현 전

## 1. 제안

생신과 축의금을 모두 **가족 캘린더의 일정**으로 관리하고, 각 일정에 **준비할 금액**을 선택적으로 붙인다. 사용자는 날짜를 기억하고, 필요한 돈을 미리 확인하고, 실제 지출을 같은 일정에 연결한다.

핵심 흐름은 `일정 등록 → 예정액 확인 → 실제 지출 기록/연결 → 지출 마무리`다. 생신과 축의금은 첫 출시부터 함께 제공한다.

## 2. 현재 앱과 연결할 지점

현재 소스 기준으로 확인했다. 기존 기획 문서와 실제 구현이 다른 부분은 실제 화면 구조를 기준으로 삼았다.

- 주 메뉴는 홈·내역·분석·자산이다. `/budget`은 현재 현금·적금·주식·대출을 다루는 자산 화면이다.
- 내역에 목록/달력 전환이 있고, `DashboardCalendar`는 거래 날짜별 수입·지출을 보여준다.
- 홈에도 선택형 달력 패널과 달력으로 가는 동선이 있다. 홈 달력 패널은 기본 표시 항목이 아니다.
- 일반 거래를 미래 날짜로 입력하면 홈과 분석의 해당 기간 지출에 포함될 수 있다. 생신 예정액을 그대로 일반 거래로 저장하면 실제 지출과 혼동된다.
- 현금 잔액은 거래의 반영일을 따로 계산하며 신용카드는 사용일과 출금일이 구분된다.

따라서 기존 달력 UI는 확장하되, 일정과 예정액은 실제 거래와 별도로 관리한다. 월 예산 기능의 추가나 복구를 이 기능의 선행 조건으로 삼지 않는다.

## 3. 화면 배치

### 홈: 앞으로 챙길 일

대표 요약 아래에 작은 카드로 제공한다. 달력 패널 표시 설정과 관계없이 진입할 수 있다.

예시:

```text
앞으로 챙길 일                       가족 캘린더 ›
10/18  민수 아버님 생신       준비할 돈 30만 원
10/25  지연 결혼식 · 축의금   준비할 돈 10만 원
11/02  수진 어머님 생신      금액 미정

앞으로 30일 준비할 돈 40만 원 · 금액 미정 1건
                                    + 일정 추가
```

- 오늘부터 30일 범위로 다음 달 초 일정까지 보여주고, 가까운 3건 이후는 전체 보기로 연결한다.
- 날짜가 지났지만 정리하지 않은 일정은 별도 `확인할 일정`으로 남긴다. 다음 날 자동으로 숨기거나 지출 처리하지 않는다.
- 일정이 없으면 `부모님 생신이나 결혼식을 미리 적어두세요`와 추가 버튼을 표시한다.
- 홈 구성원별 소비 필터와 독립적으로 가족 공유 일정을 보여준다. 개인 소비를 보는 중에도 공동 일정이 사라지지 않게 한다.

### 가족 캘린더: 기존 내역 달력 확장

초기에는 주 메뉴 4개를 유지하고, 홈의 `가족 캘린더`와 내역의 `달력`에서 동일한 화면으로 들어간다. 일정 접근성을 홈에서 확보하므로 새 메뉴가 필수는 아니다.

- 월 이동, 오늘로 이동, `일정 추가`를 상단에 배치한다.
- 보기 필터는 `전체 / 일정 / 거래`를 제공한다. 거래의 카테고리·작성자 필터는 일정에 적용하지 않는다.
- 날짜 칸에는 일정 이름 한 줄과 추가 건수, 기존 수입·지출 요약을 표시한다. 모바일에서 모든 금액과 제목을 칸 안에 밀어 넣지 않는다.
- 날짜를 누르면 아래 상세 영역에 일정과 거래를 구분해서 보여준다. 연결된 거래는 일정 상세에서도 확인한다.
- 금액은 `예정 10만 원`, `지출 10만 원`처럼 글자로 구분한다. 색상만으로 구분하지 않는다.
- 월 아래에는 `이번 달 일정 목록`과 `남은 예정액 / 금액 미정 건수`를 제공한다. 달력 칸을 하나씩 누르지 않아도 준비할 돈을 읽을 수 있다.
- 홈 전체 달력 패널도 같은 일정 데이터와 표현을 사용한다.

별도 캘린더 주 메뉴는 일정 이용 빈도가 높아진 뒤 검토한다. 첫 출시부터 별도 일정 앱 수준의 탐색 구조를 만들 필요는 없다.

## 4. 두 요구사항의 입력 경험

공통 필수 입력은 종류·제목·날짜다. 예상 지출, 담당자, 메모는 선택이다. 일정 등록 시 계좌나 결제수단을 요구하지 않는다.

| 항목 | 부모님 생신 | 결혼식·축의금 |
|---|---|---|
| 기본 반복 | 매년 | 반복 없음 |
| 날짜 | 양력/음력 선택 | 양력 행사일 |
| 대상 표시 | 민수 아버님처럼 두 사람 모두 이해할 이름 | 친구 이름 또는 행사 이름 |
| 준비할 금액 | 비워도 등록 가능, 정해지면 추가 | 예정 축의금 입력을 눈에 띄게 제공 |
| 부가 정보 | 올해 식사일·메모 | 시간·장소·메모, 모두 선택 |
| 실제 지출 | 용돈·선물·식사 등 여러 거래 연결 가능 | 송금·현금 전달 내역 연결 |

관계 명칭은 `우리 엄마`처럼 작성자에 따라 의미가 달라지는 기본값을 피한다. 가족 모두에게 같은 제목을 보여주고 담당자는 별도로 둔다. 담당자와 실제 지출 작성자는 같을 필요가 없다.

금액은 `미정 / 금액 입력 / 지출 없음`을 구분한다. 빈 금액을 0원으로 합산하지 않는다. 축의금도 금액이 아직 정해지지 않았다면 일정부터 저장할 수 있다.

### 생신 반복과 음력

- 생신은 한 번 등록하면 매년 표시한다. 출생연도나 나이는 필수가 아니다.
- 양력/음력과 원래 월·일을 보존한다. 음력은 매년 해당하는 양력 날짜로 표시하고 원래 음력 날짜를 함께 보여준다.
- 음력 윤달 생신은 윤달이 없는 해의 기념 규칙을 명시적으로 선택하게 한다. 양력 2월 29일도 평년 적용일을 선택하게 한다.
- 날짜 변환 방식은 구현 단계에서 지원 범위와 경계 사례를 검증한 뒤 채택한다. 작년 양력 날짜를 그대로 복사하지 않는다.
- 생신과 올해 식사일이 다르면 `올해 챙길 날짜`로 변경할 수 있다. 다음 해 생신의 원래 규칙은 보존한다.
- 매년 반복되는 것은 일정이다. 올해 준비한 금액과 완료 상태는 올해에만 적용한다. 작년 실제 지출은 참고로 보여주며 올해 예정액으로 자동 확정하지 않는다.
- 수정은 `이번 일정만 / 이번부터 이후 일정`을 구분하고 지난 거래는 보존한다.

## 5. 금액과 실제 지출 처리

### 집계 원칙

1. 일정 등록만으로 실제 지출, 현재 현금, 자산, 소비 분석을 바꾸지 않는다.
2. `남은 예정액`은 사용자가 입력한 예정 총액에서 해당 일정에 연결한 실제 지출을 뺀 값의 합계다. 각 일정별 최솟값은 0원이다.
3. 금액 미정 일정은 금액 합계에서 제외하되 건수를 함께 표시한다.
4. `지출 마무리`하거나 취소한 일정의 남은 예정액은 0원이다. 취소해도 이미 연결한 실제 거래는 삭제하지 않는다.
5. 미래에 쓸 돈과 카드 출금 예정액은 성격이 다르므로 하나의 소비 합계에 더하지 않는다.

예: 생신 예정 30만 원 + 축의금 예정 10만 원이면 준비할 돈은 40만 원이다. 축의금 10만 원을 지출로 기록하면 실제 지출이 10만 원 늘고, 남은 예정액은 30만 원으로 줄어든다.

생신에 20만 원을 먼저 쓰면 남은 예정액은 10만 원이다. 25만 원으로 모두 마쳤다면 `지출 마무리`를 눌러 5만 원을 더 준비할 필요가 없음을 확정한다. 실제 32만 원을 썼다면 남은 예정액은 0원이며 일정 상세에 예정 대비 2만 원 초과를 표시한다. 금액이 소진됐다고 행사 자체를 자동 완료하지 않는다.

### 지출 기록 흐름

```text
결혼식 일정 · 예정 축의금 10만 원
  → 지출 기록
  → 기존 거래 입력창에 금액·관련 메모를 채움
  → 실제 지급일·금액·결제수단·출금 보유처 확인
  → 저장 시 실제 거래와 일정 연결
  → 더 쓸 돈이 없다면 지출 마무리
```

- 실제 지급일 기본값은 기록하는 오늘이다. 행사일보다 먼저 송금했어도 정확한 지급일을 기록한다.
- 사용 가능한 지출 카테고리를 추천하되, 일정 종류와 카테고리를 같은 개념으로 고정하지 않는다. 생신의 식비와 선물비는 서로 다른 카테고리일 수 있다.
- `기존 지출 연결`도 제공해 이미 기록한 송금을 다시 입력하지 않게 한다.
- 한 일정에 여러 실제 거래를 연결할 수 있다. 첫 출시에서는 한 거래를 여러 일정으로 쪼개는 기능은 제외한다.
- 두 사람이 같은 거래를 동시에 연결하거나 저장 버튼을 다시 눌러도 중복 반영되지 않아야 한다. 완료 상태도 가족에게 공유한다.
- 연결된 거래를 수정하면 일정 실제액과 남은 예정액을 함께 갱신한다. 삭제·연결 해제로 실제액이 줄면 해당 지출 계획을 다시 확인할 상태로 돌린다.
- 반복 일정 삭제는 이후 반복 중지로 처리한다. 실제 지출이 있는 과거 일정은 기록을 보존한다.

### 행사 월과 돈을 쓰는 월

기본적으로 예정 지출일은 행사일과 같다. 필요하면 `돈을 쓸 날짜`를 따로 정할 수 있다. 준비할 돈은 예정 지출일이 속한 기간에 합산하고, 행사는 행사일에 표시한다.

예: 11월 결혼식 축의금을 10월에 미리 송금하면 실제 소비는 10월에 잡히고 11월 일정은 지급 완료로 보인다. 금액이 두 달에 걸쳐 중복으로 예정 처리되면 안 된다.

첫 출시에서는 행사 예정액을 현재 잔액에서 차감한 값을 `쓸 수 있는 돈`으로 표시하지 않는다. 그 값을 제공하려면 일반 생활비, 카드 출금, 적금·대출, 예정 수입까지 기간별로 맞추는 별도 현금 예측 설계가 필요하다.

## 6. 첫 출시 범위와 확장

### 첫 출시에서 함께 제공

- 가족 공유 일정 등록·수정, 생신/결혼식·축의금/기타 종류.
- 생신 연간 반복, 양력·음력, 해당 연도만 날짜·금액 변경.
- 금액 미정과 지출 없음 구분, 예정액 입력.
- 홈의 앞으로 30일 일정, 가족 캘린더, 월별 일정 목록.
- 실제 지출 생성·기존 거래 연결·부분 지출·지출 마무리.
- 일정 취소, 반복 중지, 날짜가 지난 미정리 일정 확인.
- 앱 안에서 D-day와 임박 표시. 앱을 열지 않아도 오는 외부 알림은 별도 기능임을 UI에서 혼동시키지 않는다.

### 후속 확장

- 사용자 설정에 따른 푸시 알림과 부부 중 누가 챙길지 표시 강화.
- 작년 같은 생신에 쓴 돈과 올해 예정액 비교, 금액 복사.
- 앞으로 12개월 행사 예정액을 보고 매달 얼마씩 준비할지 계산.
- 월 예산 기능을 도입한다면 실제 지출과 예정액을 구분해 함께 표시.
- 카드 결제일·고정 납입까지 포함한 날짜별 현금 예측.

시간 단위 일정표, 외부 캘린더 동기화, 참석자 초대, 축의금 주고받은 관계 장부는 초기 범위를 넓히므로 후속 수요가 있을 때 검토한다.

## 7. 구현 시 지켜야 할 경계

데이터는 개념적으로 `반복 일정 원본`, `해당 연도의 일정과 준비할 금액`, `실제 거래 연결`을 구분한다. 생신의 반복 규칙을 바꿔도 이전 연도의 금액과 완료 상태는 바뀌면 안 된다.

일정은 기존 가족 공유 범위에 맞춘다. 일정 작성자·담당자·실제 지급자는 별도로 취급하고 다른 가족의 거래를 연결할 수 없게 한다. 가족 두 사람이 동시에 편집하는 경우 실패·충돌을 알려주고 최신 상태를 다시 확인할 수 있어야 한다.

예정액을 일반 거래에 임시로 넣는 방식은 피한다. 기존 적금·대출의 미래 거래, 카드 결제 예정액과도 출처를 구분한다. 통계나 현금 잔액에서 제외하기 위한 예외가 화면마다 늘어나지 않게 한다.

## 8. 출시 판단 시나리오

1. 부모님 생신을 금액 없이 등록해도 부부 모두 달력과 홈에서 확인한다.
2. 음력 생신은 다음 해에 다시 입력하지 않아도 올바른 날짜에 나타나며, 윤달·평년 규칙을 확인할 수 있다.
3. 축의금 10만 원을 등록해도 현재 지출과 현금 잔액은 그대로다.
4. 해당 축의금을 실제 지급하면 지출에 한 번만 반영되고 예정액에서 빠진다.
5. 용돈과 식사비를 나눠 입력해도 한 생신의 실제 지출로 모이고, 마무리하면 잔여 예정액이 남지 않는다.
6. 행사일과 지급일이 다른 달이어도 월별 집계가 중복되지 않는다.
7. 행사 취소나 반복 중지로 과거 실제 거래가 삭제되지 않는다.
8. 올해 생신을 마무리해도 내년 생신은 미완료·금액 미정으로 새롭게 준비할 수 있다.
9. 두 사람이 동시에 지급 기록을 저장하거나 기존 거래를 연결해도 중복 거래·중복 연결을 막는다.
10. 달이 바뀌어도 아직 정리하지 않은 일정은 확인할 수 있다.
