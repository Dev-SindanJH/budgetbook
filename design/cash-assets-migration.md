# 현금 보유처 연결 및 예산 기능 제거

## 기존 데이터 처리

- 사용자가 확인한 대로 기존 `cash_assets.amount`는 현재 잔액이다. 기존 거래는 `cash_balance_included = false`로 보존하여 수입·지출을 다시 반영하지 않는다. 기존 거래를 수정·삭제해도 현재 잔액은 변하지 않는다.
- 새 거래는 보유처를 선택한다. 보유처별 현재 잔액은 저장한 기준 금액에 연결된 새 거래를 합산한다. 지출 수정·삭제·보유처 이동도 합산 결과에 반영된다. 미래 거래는 해당 날짜부터, 신용카드 지출은 결제일부터 반영한다.
- 보유처 잔액을 수동 수정하면 입력값이 현재 잔액이 되도록 기준 금액을 보정한다. 거래 합산과 중복되지 않는다.
- 보유처가 여러 개면 자동 배분하지 않는다. 기존 적금·대출에는 보유처 미지정 안내를 표시하고 수정 화면에서 선택한다. 새로 생성하는 자동납입은 이 보유처를 상속한다. 기존 자동납입을 수정하면서 오늘 거래가 재생성되어도 중복 차감되지 않도록 기존 계획의 반영 시작일은 전환일 다음 날이다.
- 기존 단일 `cash_settings`만 사용하는 가족은 종전 표시 잔액을 ‘기존 보유 현금’ 항목으로 옮긴다. 이미 현금 항목이 있다면 별도로 합산하지 않는다.
- 연결된 거래·적금·대출이 있는 보유처 삭제는 DB 외래키로 막는다. 다른 가족의 보유처도 연결할 수 없다.
- 백업 내보내기에 현금 항목을 포함한다. 거래 가져오기는 과거 내역 복원으로 취급하며 잔액에 다시 반영하지 않는다.
- 예산 UI·조회·저장 기능은 제거한다. 기존 예산 테이블은 복구를 위해 보존한다.

## 적금

홈과 자산 총액 모두 적금 상세의 `savingsAmounts(plan, today).paid`를 사용한다. 자동 생성 거래의 유무와 무관하게 가입일부터 현재까지의 납입액을 합산한다. 상세와 동일하게 이자·과거 미납·중지 기간 보정은 포함하지 않는다.

## 적용 순서

1. 운영 DB의 백업을 확보하고 구 버전에서 거래 입력을 멈춘다.
2. `supabase/migrations/20261001114150_cash_asset_transactions.sql`을 한 트랜잭션으로 적용한다. 기존 자동납입 함수를 교체하지 않아 기존 `20261002_savings_no_maturity.sql`과 함께 사용할 수 있다.
3. 환경변수가 설정된 상태로 `npm ci && npm run build`를 실행하고 새 프런트엔드를 배포한다. DB와 프런트엔드는 함께 전환해야 한다. 새 DB는 보유처 없는 새 거래를 거부한다.
4. 기존 잔액 보존, 새 지출·수입 등록, 수정·삭제, 적금 합계를 확인한다.

2026-10-01 운영 DB에 적용했다. 기존 현금 항목 2개와 거래 111건, 적금 2개의 기존 필드가 바뀌지 않았음을 같은 트랜잭션 안에서 검증했다. 기존 거래는 모두 잔액 재반영에서 제외했다. 운영 설정으로 docs 배포 파일도 갱신했다.

## 검증

- `node --test tests/asset-balances.test.mjs`
- `PGLITE_MODULE_PATH`에 설치된 `@electric-sql/pglite` 경로를 지정한 뒤 `node tests/cash-migration.mjs`: 독립 PostgreSQL에서 기존 데이터 보존, 재실행, 외래키, RLS, 자동납입 상속을 검사한다.
- `node tests/design-smoke.mjs`: `PLAYWRIGHT_MODULE_PATH`, `BROWSER_PATH`로 외부 Playwright와 브라우저를 지정할 수 있다. 실제 계정·API를 사용하지 않는다.
