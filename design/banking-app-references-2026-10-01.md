# BudgetBook 은행 앱 디자인 레퍼런스

조사일: 2026-10-01

목표: 중요한 정보를 메인에서 간결하게 확인하고, 기록과 조회가 쉬운 현대적인 금융 앱으로 개편한다.

공식 서비스 페이지, 개발사가 게시한 앱스토어 소개, 공식 디자인 글과 제품 담당자의 개편 공지를 기준으로 조사했다. 공식 홍보 화면은 로그인한 실제 앱의 모든 상태를 대표하지 않는다. 게시일이 없는 서비스 페이지는 현재 공개된 자료이며, 2026년에 새로 디자인되었다는 의미는 아니다. 아래의 BudgetBook 적용안은 이 자료와 현재 코드 구조를 바탕으로 한 제안이다.

### 토스: 기본적인 읽기 경험

앱스토어의 개발사 설명은 계좌, 수입과 소비, 카드 실적, 정기적으로 나가는 비용을 모아 보는 기능을 소개한다. TDS 글은 컴포넌트의 일관성과 큰 텍스트, 화면 읽기 접근성을 다룬다. TDS 글은 2024년 자료로, 최신 홈 화면을 증명하는 자료가 아니라 디자인 시스템 원칙을 참고하는 자료다.

적용 제안: 숫자 중심 화면, 짧은 제목, 적은 종류의 버튼, 넉넉한 행 간격. 상품 추천이나 혜택 영역을 늘리기보다는 가계부의 주요 행동에 집중한다.

### Monzo: 이번 개편의 정보 구조 기준

제품 담당자는 2026-03-10 공지에서 고객이 돈을 일상 지출과 미래 자금으로 구분한다는 조사 결과를 설명했다. 이에 홈은 일상 지출에 집중시키고 저축·투자 등을 Grow 탭에 모았다. 당시 공지는 순차 배포 계획을 밝혔으므로 모든 사용자에게 같은 날짜에 적용됐다고 단정하지 않는다.

적용 제안: 홈에서 현금·적금·주식의 상세 내역을 모두 펼치지 않는다. 자산 총액을 작은 요약으로 남기고 자세한 구성은 자산 화면으로 연결한다.

### Revolut: 요약에서 분석으로 이어지는 흐름

공식 예산 페이지는 빠른 확인과 깊은 분석을 함께 지원하는 구조, 카테고리 분류와 예산 알림을 소개한다. 미국 지원 문서는 지출·수입 위젯, 이전 기간 비교, 기간과 분류 기준 변경을 설명한다. 국가별 기능 차이가 있을 수 있다.

적용 제안: 메인은 이번 달 사용액과 지난달 같은 기간 대비 증감만 보여준다. 전체 월과 아직 끝나지 않은 월을 단순 비교하지 않는다. 카테고리 순위·추세·구성원 비교는 분석 화면에서 본다.

### 카카오뱅크·N26: 가족 가계부 특성에 맞춘 보조 기준

카카오뱅크의 모임통장은 잔액과 입출금 현황을 구성원과 공유한다. N26의 Spaces는 목적에 따라 자금을 구분하고 Shared Spaces는 공동 목표를 지원한다. BudgetBook에서는 실제 은행 계좌 개설이나 금융상품 기능이 아니라, 공동 사용 범위와 목적별 묶음이라는 표현 방식을 참고한다.

## 2. 현재 BudgetBook에서 바꿀 부분

로그인한 화면의 사용성 테스트가 아닌 소스 구조 검토 결과다.

- `src/index.css`: 베이지 배경, 골드 포인트, 여러 방사형 그라데이션, 반투명 표면과 그림자가 기본이다. 이번 요구에는 밝은 중립색 배경과 선명한 숫자, 제한된 포인트 컬러를 제안한다.
- `src/pages/Dashboard.jsx`: 수입, 지출, 예상 현금 흐름, 총 보유 자산, 현금, 주식, 미래 카드값이 여러 요약 카드로 배치된다. 총 자산과 구성 자산의 반복 노출을 줄이고 대표 지표를 정한다.
- 달력, 색칠 가계부, 자동이체 상세, 카테고리 비중, 가족별 지출은 필요한 정보지만 기본 홈의 길이와 복잡도를 높일 수 있다. 목적에 맞는 화면으로 재배치하고 홈에는 요약을 남긴다.
- 현재 경로는 홈·거래 내역·통계·예산/자산 관리·설정으로 구성된다. 모바일에서는 홈·내역·분석·자산을 주요 탭으로 제안하고, 예산 설정은 소비 요약에서 바로 접근하게 한다.

## 3. 추천 디자인 방향

**토스의 읽기 쉬운 구성 + Monzo의 일상/자산 분리 + Revolut의 간결한 소비 분석 + 부드러운 글래스 표면.**

추가 사용자 선호: 반투명 카드·패널을 활용한 세련된 글래스모피즘. 추천 A를 기본으로 유리 질감을 결합한다.

### 글래스모피즘 적용 방향

카드·패널은 정보를 담는 구성 요소이고, 글래스모피즘은 그 표면을 표현하는 스타일이다. 반투명 표면, 배경 흐림, 얇은 빛 테두리, 부드러운 그림자로 깊이를 표현한다.

[Apple Materials 가이드](https://developer.apple.com/design/human-interface-guidelines/materials)와 [Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/)는 Liquid Glass를 콘텐츠 위의 탐색·조작 계층에 적용하고, 유리 표면끼리 겹치는 사용을 피하도록 설명한다. Liquid Glass는 동적인 광학 효과까지 포함하는 Apple의 재질 체계로, 웹의 단순 배경 흐림과 동일하지 않다.

BudgetBook 적용 제안:

- 하단 탭 바·상단 도구 모음: 유리 질감을 가장 분명하게 보여주는 영역.
- 대표 예산 카드: 숫자가 선명한 우윳빛 반투명 표면과 은은한 가장자리. 이는 자체적인 웹 스타일 제안으로 Apple의 콘텐츠 카드 적용 권장이라는 뜻은 아니다.
- 최근 내역·차트: 불투명에 가까운 밝은 표면으로 긴 텍스트와 작은 숫자의 가독성 유지.
- 배경: 옅은 블루·라벤더 색 번짐을 일부 배치해 유리 표면의 깊이를 표현.
- 기록 시트: 하나의 표면으로 띄우고, 그 안에 반투명 카드를 여러 겹 쌓지 않기.
- 실제 구현 검토: 스크롤 중 숫자 대비, 모바일 흐림 효과 성능, 투명 효과를 줄이는 대체 표면 확인.

현재 코드에도 반투명 표면과 배경 흐림이 있다. 개편은 효과를 추가하는 데 그치지 않고, 골드·베이지 색감과 정보 밀도를 함께 바꾸어 원하는 인상을 만든다.

| 방향 | 색상 제안 | 분위기 | 적합성 |
| --- | --- | --- | --- |
| A. 밝은 금융 앱 — 추천 | 배경 `#F5F7FA`, 표면 `#FFFFFF`, 본문 `#191F28`, 포인트 `#316DFA` | 밝고 선명하며 익숙한 사용감 | 정보 확인과 기록이 잦은 가족 가계부 |
| B. 차분한 자산 관리 | 배경 `#F4F7F6`, 본문 `#183B35`, 포인트 `#147D64` | 차분하고 절제된 인상 | 저축 목표·자산 관리 강조 |
| C. 대비가 강한 금융 앱 | 중립 배경, 진한 네이비 대표 카드, 제한된 라임 포인트 | 강한 숫자 대비와 개성 | 자산 총액 중심 화면 |

색상은 자체 제안이며 각 서비스의 공식 브랜드 토큰을 복제한 값이 아니다. 실제 적용 시 상태별 대비를 검증한다.

추천 A의 세부 규칙:

- 대표 금액은 32–36px, 섹션 제목은 18–20px, 일반 텍스트는 14–16px에서 시작한다.
- 카드 반경은 20px 전후, 모바일 좌우 여백은 20px 전후. 그림자는 최소화하고 여백으로 영역을 구분한다.
- 전체 지출 금액은 기본 텍스트색으로 표시하고, 예산 초과·실패처럼 주의가 필요한 상태에 경고색을 사용한다. 색과 함께 상태 문구도 보여준다.
- 이모지 중심 장식은 일관된 선형 아이콘으로 정리한다. 버튼에는 동사를 포함한 라벨을 쓴다.
- 모바일 핵심 버튼은 충분한 터치 영역을 제공하고, 큰 글씨 설정과 키보드 탐색을 고려한다.

## 4. 홈의 권장 정보 순서

1. 상단: 현재 월, 가족 전체/구성원 선택, 설정 접근.
2. 대표 영역: **이번 달 남은 예산**. 사용액 / 설정 예산과 진행 막대를 함께 표시한다.
3. 보조 요약: 이번 달 지출, 가장 가까운 카드 결제일과 예정 금액.
4. 주요 행동: **지출 기록**을 가장 눈에 띄게 배치하고 수입 기록을 보조로 제공한다.
5. 자산 요약: 총 보유 자산을 한 줄로 보여주고 자산 화면으로 연결한다.
6. 최근 내역: 3–5건과 전체 보기.

예산을 설정하지 않은 사용자는 대표 영역에 이번 달 지출과 예산 설정 버튼을 보여준다. 초과 상태는 음수를 그대로 크게 보여주기보다 “예산보다 12만 원 더 썼어요”처럼 의미가 명확한 문구로 표현한다.

남은 예산은 현금 잔액이나 실제 출금 가능한 돈과 다르다. `이번 달 남은 예산`이라는 명칭을 유지하고, 계산 기준에서 어떤 지출을 포함하는지 확인할 수 있어야 한다. 현재 코드의 카테고리 예산 합계와 전체 지출을 사용할 경우, 미설정 카테고리 처리 규칙을 먼저 정한다.

카드 사용액은 소비에, 카드 결제 예정액은 현금 유출 일정에 표현한다. 같은 금액을 소비로 두 번 합산하지 않는다. 총 보유 자산을 부채 차감 없는 상태에서 순자산으로 바꾸어 부르지 않는다. 시세 미확인·데이터 미설정은 0원과 구분한다.

## 5. 상세 화면과 사용 흐름

- 내역: 날짜별 목록을 기본으로 하고 달력 보기로 전환. 수입/지출, 구성원, 카테고리 필터 제공.
- 분석: 카테고리별 지출, 가족별 지출, 이전 기간 대비와 추세를 배치.
- 자산: 현금·적금·주식·대출을 묶고, 보유액과 부채의 의미를 분리. 주식 시세 기준 시점 표시.
- 예산: 홈의 남은 예산 영역에서 접근해 카테고리 한도를 조정. 색칠 가계부는 예산 상세나 선택 가능한 홈 영역으로 유지할 수 있다.
- 기록: 모바일에서는 금액 입력부터 시작하는 하단 시트, 데스크톱에서는 대화상자. 자주 쓰는 카테고리와 직전 선택을 활용해 입력 단계를 줄인다.
- 저장 결과: 성공 피드백과 수정·취소 접근을 제공. 전송 중에는 중복 저장을 막고 실패 시 입력 내용을 유지한다.
- 데스크톱: 모바일의 세로 목록을 그대로 확대하지 않고, 주요 정보와 최근 내역을 넓은 영역에, 예정 결제와 자산 요약을 보조 영역에 배치한다.

## 6. 시안 검토 기준

- 첫 화면에서 이번 달 소비 상태와 다음 행동을 바로 찾을 수 있는가?
- 보유 자산, 예산 잔액, 예정 결제의 의미가 서로 혼동되지 않는가?
- 기록 버튼이 스크롤 위치에 따라 찾기 어려워지지 않는가?
- 대표 카드 외의 정보가 같은 강도로 경쟁하지 않는가?
- 예산 미설정, 거래 없음, 예산 초과, 긴 금액, 데이터 조회 실패도 읽기 쉬운가?
- 가족 전체인지 특정 구성원인지 현재 조회 범위가 분명한가?

이 문서는 디자인 레퍼런스와 개편 방향을 정리한다. 후속 요청에 따른 실제 적용 범위와 검증 결과는 [디자인 적용 결과](redesign-implementation.md)를 참고한다.
