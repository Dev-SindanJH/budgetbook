# 가족 캘린더 구현 결과

2026-10-02. `family-calendar-plan.md`의 첫 출시 범위를 구현했다.

## 사용 흐름

- 홈 대표 요약 아래의 **앞으로 챙길 일**에서 가까운 3건, 앞으로 30일 준비할 돈과 금액 미정 건수를 확인한다. 지난 미정리 일정은 별도로 펼쳐 본다.
- **내역 → 달력**에서는 가족 일정과 거래를 함께 보거나 따로 볼 수 있다. 날짜 선택과 월별 목록에서 상세를 연다. 거래용 구성원·카테고리 필터는 가족 일정을 숨기지 않는다.
- 생신은 양력/음력과 매년 반복을 지원한다. 윤달이 없는 해는 평달에 기념하거나 건너뛸 수 있고, 양력 2월 29일은 2월 28일/3월 1일을 선택한다.
- 결혼식·축의금 등록은 행사일과 예정 축의금을 중심으로 입력한다. 금액 미정으로 저장하거나 지출 없음으로 표시할 수도 있다.
- 일정 상세에서 **이 일정에 지출 기록** 또는 **기존 지출 연결**을 사용한다. 실제 지출의 기본 날짜는 오늘이며 행사일보다 먼저 지급할 수 있다.
- 여러 지출을 연결하면 실제 지출과 남은 예정액을 함께 보여준다. **지출 마무리**는 남은 예정액만 정리하며 거래는 남긴다.
- 실제 거래를 줄이거나 삭제·연결 해제하면 마무리했던 일정은 다시 준비 중으로 돌아온다. 취소한 일정의 실제 거래도 보존한다.
- 반복 수정 범위는 이번 일정만/이번부터 이후 일정이다. 별도로 수정하거나 실제 거래를 연결한 이후 일정은 유지한다. 이후 반복 중지는 지난 기록과 실제 지출을 보존한다.
- 내역 목록의 **연결된 가족 일정**에서 원래 일정으로 이동한다.

## 데이터와 배포 상태

- `family_events`: 반복의 기본 규칙과 공유 수정 버전.
- `family_event_occurrences`: 각 연도의 날짜, 메모, 담당자, 예정액, 상태. 미래 연도는 금액 미정으로 생성한다.
- `transactions.family_event_occurrence_id`: 실제 지출과 일정 연결. 같은 가족인지 복합 외래키와 검증 함수로 검사한다.
- 예정액은 거래 테이블에 저장하지 않으므로 기존 소비·현금·자산 집계에 영향을 주지 않는다.
- 저장 함수는 가족 권한을 그대로 적용하는 SECURITY INVOKER다. 공유 버전과 행 잠금으로 동시 편집을 확인하고 지출 등록 요청 ID로 재시도 중복을 막는다.
- 새 테이블의 RLS, 비로그인 접근 차단, Realtime 등록을 확인했다. 여러 연도의 알림이 한 번에 올 때 조회 요청은 묶어서 처리한다.
- 마이그레이션 `20261002032103_family_calendar.sql`을 연결된 BudgetBook Supabase 프로젝트에 적용했다. 기존 금융 데이터를 수정하는 백필은 없다.
- `schema.sql`에도 신규 설치용 정의를 포함했다. 기존 DB에는 새 마이그레이션을 한 번만 적용한다.
- `docs/` 배포 산출물을 재빌드했다. Git 푸시와 프런트엔드 공개 배포는 수행하지 않았다.

## 범위와 날짜 지원

- 한국 음력 변환에 고정 버전 `korean-lunar-calendar@0.4.0`을 사용한다. [라이브러리 문서](https://github.com/usingsky/korean_lunar_calendar_js)에 따라 변환 결과를 검증했다.
- 완전한 연도 범위를 제공하기 위해 앱의 음력 반복 지원은 1900~2049년, 양력은 1900~2100년이다. 음력 30일이 없는 해는 해당 월 마지막 날에 표시한다. 입력 화면에 범위와 처리 규칙을 안내한다.
- 알림은 앱 내 D-day와 지난 일정 확인까지다. 푸시 알림·외부 캘린더 연동은 후속 범위다.
- JSON 내보내기에 일정·연도별 기록·연결 정보를 포함한다. 기존 가져오기는 거래만 지원하며 설정 화면에 이 범위를 명시했다.

## 검증

- `npm test`: 날짜 변환, 반복, 부분 지급, 미정/0원, 초과, 취소, 행사월/지급월 구분 및 기존 자산·금액 테스트.
- `npm run test:calendar-db`: PGlite의 실제 PostgreSQL 엔진에서 신규 마이그레이션과 저장 함수를 실행. 실제 지출과 예정 분리, 재시도 중복 방지, 오래된 버전 거절, 실패 시 원자적 취소, 연결/해제, 거래 수정/삭제 후 재개, 반복 중지 시 기록 보존, 가족별 RLS·비로그인 차단 검사.
- `npm run test:calendar-ui`: 모의 계정/데이터 환경에서 홈 요약, 생신·축의금 등록, 실패 후 입력 보존, 기존 지출 연결, 마무리, 부분 지출, 반복 수정, 달력 필터를 조작. 데스크톱과 390px/320px 모바일에서 넘침 검사 및 스크린샷 확인.
- `node tests/design-smoke.mjs`: 기존 화면·거래·자산·설정·인증 화면의 회귀 검사.
- `npm run build`, `git diff --check`.
- 운영 DB에서는 추가된 테이블/함수/정책/Realtime을 조회해 확인했다. 실제 사용자 계정으로 운영 금융 거래를 생성하는 브라우저 테스트는 수행하지 않았다.

Supabase 보안 진단에서 이번 기능의 신규 경고는 없었다. 변경 전부터 있던 [함수 search_path](https://supabase.com/docs/guides/database/database-linter?lint=0011_function_search_path_mutable), [기존 SECURITY DEFINER 함수 권한](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable), [유출 비밀번호 보호 설정](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) 경고는 동일하게 남아 있다.

화면 검증 이미지는 `.test-results/family-calendar/`에 저장한다. 테스트 픽스처는 앱 빌드에 포함하지 않는다.
